# Scheduling boundary: cross-boundary access inventory (Phase 0, Session 2)

Scope: every read and write of `ExamSession`, `Booking`, `Waitlist`, and of the reference tables they join (`Exam`, `TestCenter`, `Room`, `Candidate`), by anything **other than** the four booking procs (`db/procs/020`-`023`) and their triggers (`db/triggers/032`, `033`). Line numbers are from `estate/legacy-baseline` at the commit this branch forked from. Legacy behaviour, defects included, is the spec. HB-xx = `docs/as-is/hidden-behaviours.md`.

Executable pins: `services/scheduling-contract-tests/` (see [README](../../services/scheduling-contract-tests/README.md)). The **Pinned by** column names the test class (`RA` = `ResultsAttendContractTest`, `BA` = `BookingApiContractTest`, `PR` = `PortalReadContractTest`, `RE` = `RetakeEligibilityContractTest`, `IG` = `InventoryGuardTest`, which fails if a cited SQL or LINQ line moves or changes).

Replacement types used in the last column:
- **API**: call to `scheduling-service` ([OpenAPI](scheduling-service-openapi.yaml), [narrative](scheduling-service-contract.md)).
- **Absorbed**: the logic moves inside a scheduling-service command; the caller stops doing it.
- **Ref-local**: the caller keeps reading the reference table in `AssessmentDelivery`, which stays the system of record for `Exam`/`TestCenter`/`Room`/`Candidate`. scheduling-service holds a replica (no cross-DB FKs).
- **Event**: scheduling-service publishes a domain event, or consumes a reference-data change event.
- **Results-local**: data owned by results-service; the scheduling join is replaced by values denormalised at ingest.

Transaction and lock defaults: EF6 reads run outside any explicit transaction at READ COMMITTED with shared locks released per statement and no hints. Spring `@Transactional` methods run at READ COMMITTED with no lock hints (HB-29). No caller uses `UPDLOCK`/`HOLDLOCK`; only the procs do (`020:34`, `021:26`, `022:25`).
